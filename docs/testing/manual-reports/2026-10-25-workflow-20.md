## Implementation decisions

- Existing `all`, `student`, `faculty`, `staff`, and `specific` scopes remain available. `specific` still requires individual users and stores no role selection.
- `custom` combines the deduplicated union of active users in selected allowlisted roles (`student`, `faculty`, `research_staff`) and explicitly selected active users. Empty custom unions are rejected.
- Migration 035 adds `custom` to the date-scope enum and nullable JSON columns `audience_roles` and `audience_user_ids`. The second column is needed to distinguish exact manually checked IDs from role-expanded recipients when editing a saved custom audience; the participant rows continue to represent the final union for invitations and attendance.
- Both single-date and per-date forms use distinct POST names and role/user input IDs. Role checkboxes and the existing filtered user picker are scoped to each date. The picker is enabled for `specific` and `custom`; role checkboxes are enabled only for `custom`.
- Loading legacy `specific` rows with null `audience_user_ids` falls back to their currently invited participant IDs. Existing preset scopes do not turn their expanded participant lists into manual selections on edit.
- The schedule form now requires both audience columns (migration 035) before loading/saving the upgraded schedule workflow. No changes were made to migration 034.

- During final source review, validation-error rerendering was found to mark role-expanded recipients as individually selected. The form now restores only `manual_recipient_ids` (while retaining the selected role checkboxes), and the DB-free source assertion covers that mapping. A first parent-side JavaScript parse command also failed because of PowerShell escaping; rerunning with index-based script extraction parsed successfully.
- The first source assertion invocation used Python’s Windows default encoding and failed decoding a UTF-8 character in the activity form. It was rerun with explicit UTF-8 reads; all assertions passed.
- A later attempt to rerun all checks in parallel failed before several commands launched because Windows PowerShell could not initialize its CLR under concurrent sessions. The final PHP lint, audience tests, JavaScript parse, source assertions, and diff check were run individually and passed.
- These were test-command/environment issues, not source findings. The successful reruns are the reported check results.
